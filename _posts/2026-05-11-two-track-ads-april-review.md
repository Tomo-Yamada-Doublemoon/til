## 「まず地図を描いてもらう」という発想

4月後半のADS月次課題は、**自動化ツールの企画と実装**がテーマでした。

ステップ1・2（前提知識・講義おさらい）は自分でこなせた。でもステップ3以降——「何をどの順番で、どう進めるか」——を整理しようとすると、途端に手が止まる。

そこでやったのが、**AI搭載ブラウザDiaに「進め方プラン」の叩き台を作らせる**こと。自分が考えるより先に、Diaに全体像を言語化させてから動き始める作戦です。

## Diaが出してくれたプラン全体像

Diaが生成したプランのビジュアルがこちらです。

![DiaがまとめてくれたADS月次課題の進め方プラン](/assets/img/2026-05-11-ads-monthly-plan-with-dia.jpg)
_AI-Driven School 月次課題「朝ダッシュボード」進め方プラン by Dia（2026年4月29日）_

提出期限・トラック構成・9日間のタイムラインが一枚に収まっています。これを見ながら4月後半を動きました。

## 出てきた「2トラック並行」という構造

Diaが整理してくれたプランの核心は、課題を**2つのトラック**に分けることでした。

| トラック | 目的 |
|---|---|
| **Track A**（技術練習） | AIニュース自動取得ツールをカスタマイズして、Cursor・Tailwind CSSの操作感を掴む |
| **Track B**（課題提出） | 朝のセルフチェック → 今日のダッシュボードを設計・実装する |

Track Aは「練習台」と割り切る。完璧に仕上げる必要はなく、**4パーツ構造（トリガー・ソース元・処理・届け先）の実装感覚をつかめれば十分**というラインを最初に決めたのが、精神的にラクでした。

> Track Aで詰まっても課題には関係ない、と最初に決めておくのがポイント。
{: .prompt-tip }

## 朝ダッシュボードの「4パーツ」フレームワーク

Track Bのテーマ「朝のセルフチェック → 今日のダッシュボード」を整理するにあたって、Diaが使ったフレームが**4パーツ構造**です。

| パーツ | 役割 |
|---|---|
| **トリガー** | いつ動かすか（朝の起床後 → PC起動時） |
| **ソース元** | データの入力元（スマホからの体調・エネルギー・やりたいこと） |
| **処理する場所** | GitHub Actions / GAS / Cursor Automationのどれか |
| **届ける先** | Slack / メール / Surge.sh など |

この時点で「ソース元」と「届け先」はまだ未定でした。でも**未定のまま先に動ける部分を動く**というのがDiaプランの肝。ニュースツールのカスタマイズ経験を積んでから決める、という順番です。

> 全部決まってから動こうとすると動けない。「今決められること」だけ決めて進むのがAI時代の計画術かもしれない。
{: .prompt-info }

## 振り返ってみて

4月後半を通じて気づいたのは、**計画フェーズをAIに外注する**というアプローチの有効性です。

自分でゼロから計画を立てると、「どこまで細かく決めるか」「何から始めるか」で消耗します。DiaのようなAIに叩き台を出させると、**批評・修正モード**に頭が切り替わるので、エネルギーの使い方が変わる。

「AIに何かを作らせる」のと「AIに一緒に考えさせる」は別物だと実感しています。

---

💡 **OHOポイント:** 計画立案そのものをAIに任せると、自分は「動く人」に専念できる。課題が進まない時、詰まっているのは「実装」ではなく「計画」かもしれない。

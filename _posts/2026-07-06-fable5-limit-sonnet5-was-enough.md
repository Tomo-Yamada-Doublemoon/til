Xで見かけた一つの記事がきっかけだった。「Fableはすごい。でも、本当にすべての人にFableが必要なんだろうか?」という問い。Fableでやっていることを下位モデルのSonnetでも実現できるんじゃないか、という発想で作られたプロンプトが紹介されていた。

**こんな人に読んでほしい:** Claudeのモデル選びで「結局どれを使えばいいのか」迷っている人、AIの出力が甘く(採点が緩く)なりがちで困っている人。

**この記事でわかること:**
- 「審判」と「破壊者」を分けるだけで、AIの自己採点が辛口になる理由
- フル装備を毎回回すより「軽量コア＋必要時だけ拡張」が効く理由
- Fableと対話しながらプロンプトを磨き、実際にスキルとしてパッケージ化するまでの流れ

## きっかけ:Fableは本当に全員に必要なのか

自分がやっていることに対して、Fableはオーバースペックなんじゃないかとはうすうす感じていた。そんな中でXで見かけたのが、まさにその感覚を言語化してくれる記事だった。「Fableでやっていることを、下位モデルのSonnetでも実現できるんじゃないか」という発想のプロンプトが紹介されていて、しかもFableはClaudeのプロプランだと今日までしか使えない、という個人的な制約もあり、このタイミングでFableに直接相談してみることにした。

## 最初の案:5役職×3周

最初にFableに投げたのは、こんな骨格のプロンプトだった。

```text
戦略家 → 設計者 → 生成者 → 破壊者 → 仕上げ屋
これを1周目(方向性)→2周目(弱点を壊す)→3周目(完成形)の3周回す

生成者は必ず3案出して比較し、破壊者は褒めずに壊す。各周で判断・理由・不足情報・失敗リスク・改善案・次にやること・自己採点(100点満点)を出す——という設計だった。

▎ ヒントやコツ
▎ {: .prompt-tip }

これを試しながらFableと詰めていく中で見えてきたのが、「破壊者が壊した直後に、同じロールが採点までやると点数が甘くなる」という問題だった。

発見:審判と破壊者を分けると辛口になる

Fableとのやり取りで出てきた結論はシンプルだった。

▎ おすすめは「④破壊者と採点者を分離する」＋「①ルーブリック先出し」の組み合わせです。採点の「物差し」がないと、AIは基準を自分で作りながら採点することになり、結果的に甘くなります。同じロールが「壊す」→「採点する」を続けてやると、壊した安心感でそのまま点数も甘くなりがちです。
▎ {: .prompt-info }

▎ ルーブリック: 採点項目とその配点・減点条件をあらかじめ明文化した採点基準表のこと。
▎ {: .prompt-info }

つまり、根本原因は2つだけだった。①採点基準を先に固定する、④採点役(審判)を壊す役(破壊者)から独立させる。これさえ押さえれば、残りは精度を上げる追加の縛りにすぎない。

Sonnet向けの軽量コア版

この2点を踏まえてFableが再設計してくれたのが、5役×3周のフル装備ではなく「4役×1周＋審判の再登場」という軽量版だった。理由は、Sonnetはコンテキスト圧縮に弱く、5役×3周×7項目を1チャットで回すと後半が薄くなること、そして実務で3周フルが必要な案件は月に数回で、日常は1周で足りるからだ。

【0. 審判】(最初に1回だけ)
・勝利条件を1文で定義
・採点ルーブリックを作る(5項目×20点、各項目の減点条件を明記)
・「100点の状態」「60点の状態」を具体的に1行ずつ書く

【1. 戦略家】読者の欲望・反論・勝ち筋を分析
【2. 生成者】3案出して比較→1案採用(理由付き)
【3. 破壊者】採用案を褒めずに壊す。退屈・AIっぽさ・嘘っぽさを指摘
【4. 修正者】破壊者の指摘を反映して完成形に

最後に【審判】が再登場し、ルーブリックに沿って減点方式で採点。
「あと○点上げるには何が必要か」を必ず書く。

本気の案件用:拡張モード(ボス戦モード)

保存版記事やサービスのLPなど、フル3周相当が必要な案件のために、チャットを3つに分けて元の密度を再現する「拡張モード」も用意した。

- チャット1: 審判＋戦略家＋生成者(方向性)→結果をコピー
- チャット2: 破壊者のみ(前の結果を貼って徹底破壊)
- チャット3: 修正者＋審判(完成＋最終採点)

▎ チャットをまたぐと記憶が消える(コンテキスト＝AIの作業机がリセットされる)ので、前のチャットの最後に「次のチャットに貼る用の要約」を作らせておくと、コピペ1回で済みます。
▎ {: .prompt-warning }

呼び出し方も合言葉で切り替える設計にした。「拡張モードで」「ボス戦モードで」と言えば3チャット分割の手順を案内し、指定なしなら軽量コアが1チャットで完結する。

スキル化して、リポジトリへ

最終的にこの一連の設計を「制作チーム(production-team)」スキルとしてパッケージ化してもらった。合言葉切り替え、審判の独立ロール化、引き継ぎサマリーの自動生成、そして今がチャット1〜3のどれかを貼られた内容から自動判定するロジックまで含めた形だ。

Fable自身はGitHubに直接プッシュできないので、手元での取り込み手順(git add → git commit → git push)を教えてもらい、claude-skillsリポジトリに追加した。

結論

5役×3周のフル装備をSonnetでそのまま再現しようとしても、後半で密度が薄くなって失敗する。効いたのは「審判と破壊者の役割分離」と「ルーブリック先出し」の2点だけで、これを押さえた軽量コア＋必要時だけ3チャットに分割する拡張モード、という構成にしたことで、Fableを使わなくても普段の記事・資料作りには十分な密度が出せるようになった。実際、この設計そのものが今も使っている制作チームスキルとして残っている。

次に検証したいこと

同じお題を軽量コア版とFableに直接投げた場合とで、実際どこまで出力の質に差が出るのかを一度並べて比較してみたい。

💡 OHOポイント: 上位モデルの価値は「賢さを持っていること」ではなく、その賢さを使って「下位モデルでも辛口になれる仕組み(役割分離＋基準先出し)」を設計できることにあるのかもしれない。

## この記事でわかること

- CursorのAIチャットにロール指定プロンプトを使うと、整理プランが具体的に出てくること
- プロジェクト単位・フォルダ全体、スケールによって整理の切り口が変わること
- 「わからなければAIに聞く」が、環境整理という文脈でも使えると腑に落ちた体験

## こんな人向け

ADS課題を進めているうちに、Cursorのワークスペースにプロジェクトが増えすぎて「なんとなく散らかってる感」があるけど、どこから手をつければいいかわからない人。

## 前提

- 使ったツール: Cursor（AIチャット機能）
- OS: macOS
- 課題フェーズ: 第6回講義後の環境見直しタイミング

---

## きっかけは第6回講義

第6回の講義を受けて、改めて自分のGitとGitHubへの理解を振り返った。

「なんとなく使っている」状態から、もう少し解像度を上げたい。それと同時に、ずっと気になっていたことがあった。

**一つのワークスペースに、複数のADS課題プロジェクトが全部入っている。**

`AI-news`、`morning-dashboard`、`visibility-workspace`、`RSS-news`……フォルダを開くたびに、なんとなくムリ・ムダ・ムラがある気がしていた。でも「気がする」だけで、何が問題なのかを言葉にできていなかった。

今回はこれをCursorのAIチャットで確認してみることにした。

---

## プロンプト① シニアエンジニアにレビューを頼む

最初に使ったプロンプトはこれ。

```
開いているフォルダをGitとGitHubで管理するために整理目的で最適化したいです。
Anthropic社のシニアエンジニアとしてレビューしてプランを作成してください
```

**Git:** ファイルの変更履歴を記録する仕組み。「いつ・何を変えたか」を追跡できる。  
**GitHub:** Gitで管理したファイルをクラウドに保存・公開できるサービス。

ロール指定（「シニアエンジニアとして」）を入れることで、ざっくりした質問でも専門的な視点でプランが返ってくる。

ただ、出てきたプランは専門用語が多くて、正直そのままでは消化できなかった。

> 「わからなかったら聞き直す」もプロンプト設計のうち。
{: .prompt-tip }

---

## プロンプト② 新卒向けに言い直してもらう

そこで、すぐに続けてこう投げた。

```
作成したプランを新卒の社会人でもわかるように説明してください
```

これで、なんとなく感じていたムリ・ムダ・ムラが言語化された。

- **ムリ:** 性格の違うプロジェクトが同じGit管理下に混在している
- **ムダ:** 課題ごとの変更履歴が混ざって、後から追いにくい
- **ムラ:** プロジェクトによってGit管理されているものとそうでないものがバラバラ

「何が問題か」がわかると、「何をすればいいか」も見えてくる。

まだわからないのは「整理した後、各プロジェクトの影響範囲がどう変わるか」だったが——**これは作業前にまた聞けばいい**、と思えた。この感覚が地味に大事だった。

---

## ローカルフォルダも見直す——workspaceからDeveloperへ

プロジェクト単体の整理と並行して、もう一つ気になっていたことがあった。

ローカルのホームフォルダに、GitHubリポジトリをまとめている`workspace`というフォルダがある。第6回でマコなりさんが紹介していたのは`src`フォルダだったが、他にも選択肢があるのか気になってリサーチした。

結果、**Mac環境では`Developer`フォルダもよく使われる**ことがわかったので、`workspace`→`Developer`にリネームした。

> **リポジトリ:** GitHubに保存したプロジェクトの単位。フォルダ1つ＝リポジトリ1つのイメージ。
{: .prompt-info }

---

## プロンプト③ Developerフォルダ全体にも同じプロンプトを投げる

全プロジェクトが入った`Developer`フォルダをCursorで開き、同じプロンプトを投げてみた。

```
開いているフォルダを最適化したいです。
Anthropic社のシニアエンジニアとしてレビューしてプランを作成してください
```

出てきたプランは、プロジェクト単体へのものとは**全然違う切り口**だった。

単体のときは「このプロジェクトをどうGit管理するか」という視点。  
全体のときは「フォルダをどう分類・整理するか」という視点。

**スケールが変わると、整理の視点も変わる。** 当たり前のようで、体験して初めて腑に落ちた。

---

## 今日の一番の気づき

今までだったら「どうやって整理しよう……」と考えながら調べ始め、何を調べているかわからなくなって、結局そのまま開発を進めていたと思う。

今回は**立ち止まって、環境整理そのものを目的にできた**。

そして「わからなければまずAIに聞く」を、コードじゃない文脈でも実践できた。マコなりさんが言っていたことが、もう一段階腑に落ちた感覚がある。

---

## 再現手順（3ステップ）

1. 整理したいフォルダをCursorで開き、「シニアエンジニアとしてレビューしてプランを作成して」と投げる
2. 専門用語が多ければ「新卒向けに言い直して」と続ける
3. プロジェクト単体・フォルダ全体、両方のスケールで試してみる

## この記事で出た用語

| 用語 | 一行定義 |
|---|---|
| Git | ファイルの変更履歴を記録・管理する仕組み |
| GitHub | Gitで管理したファイルをクラウドで保存・公開できるサービス |
| リポジトリ | GitHubに保存したプロジェクトの単位（フォルダ1つ＝1リポジトリのイメージ） |
| ロール指定 | AIに「〇〇として回答して」と役割を与えるプロンプトの技法 |

💡 **OHOポイント:** 「わからなければAIに聞く」は、コードを書くときだけじゃなく、環境を整えるときにも使える。
